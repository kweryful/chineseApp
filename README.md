# Dialogue Workshop

A local web app for turning Chinese textbook dialogues into sentence-level listening clips.

## Run locally

Requires Python 3.10 or newer.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload
```

Open <http://127.0.0.1:8000>. The app binds to the local machine by default. Audio is processed by the local Python server. FFmpeg is provided by the `imageio-ffmpeg` Python package.

## Workflow

1. Enter the dialogue text and choose its MP3. Speaker labels such as `大卫：` are removed. A leading unpunctuated chapter heading is kept as the dialogue name and is also checked against the audio.
2. Select **Prepare & auto-sync**. The app creates line candidates, transcribes Mandarin speech locally, and matches the dialogue in order, skipping spoken lesson numbers and other unmatched introductions. Within speaker-labelled dialogue, an unlabelled wrapped continuation is joined to the preceding speaker turn when the text ends mid-sentence. The same button moves into the editor as **Auto-sync lines** so you can run matching again after editing line text. Comma-separated text is initially split into candidate clauses. During auto-sync, clear clause cues such as `不过`, `可是`, `结果`, `实在`, `就`, `我没做完`, and `然后` start a new line; paired constructions such as `不但……还得……` stay together. Other comma-separated clauses are combined unless the recognized speech has a pause of at least 0.4 seconds. Sentence-ending punctuation always starts a new line. If a leading heading such as `马克介绍自己学习汉语的方法` is spoken, it is included as the first timed line; if it is not spoken, it remains only the dialogue name. At boundaries between matched lines, auto-sync checks the decoded waveform and trims each clip to the nearest edge of a detected quiet section, removing the pause from both clips rather than placing a shared boundary in its middle. When a quiet section cannot be detected, the waveform-based timing uses only a short lead-in before recognized speech rather than a long silence cushion. Each line has its own padded waveform and **Listen** control. Drag across a line waveform to set or adjust its start and end; click within the selected clip to audition it, or click the surrounding waveform to listen to the nearby audio. Lines the recognizer cannot match can be timed the same way.
3. Generate editable English translations and, separately, Chinese Support 3-style readings, ruby, and dictionary glosses. Export a ZIP containing one MP3 per line and `dialogue.json` / `dialogue.csv` with the line text, timing, and study fields. The English translation remains in the `gloss` field for compatibility.

Automatic sync uses the `base` faster-whisper model on the CPU. The first sync downloads the model from Hugging Face (about 150 MB); later syncs use the cached local copy. English translations use Argos Translate on your computer; the first translation downloads the Chinese-to-English model, which is then cached locally. Dialogue text and audio are not sent to a transcription or translation service. Set `DIALOGUE_WHISPER_MODEL` before starting the app to select another faster-whisper model size, such as `small`.

Translations are generated by `glossing.py` through `/api/translations`. The app installs the Argos Chinese-to-English model on first use; this one-time setup requires an internet connection. If the download fails, the app reports the issue and does not use an online translation service. Generated translations remain editable before export.

**Generate readings, ruby & glosses** uses the pinyin and dictionary features from [Chinese Support 3](https://github.com/kweryful/anki-chinese-support-3), adapted to run locally without Anki. The first use downloads and verifies its approximately 76 MB dictionary. The generated reading applies the common `一`/`不` tone changes; ruby and dictionary glosses use the add-on's local Chinese Support engine. Expand a line's study-fields section to edit each field in its tone-colored visual editor, or choose **Edit HTML** to edit its markup directly. Changes made in HTML mode are sanitized to preserve only tone spans, ruby annotations, and line/rule breaks when returning to the visual editor. All outputs are included in the export.
